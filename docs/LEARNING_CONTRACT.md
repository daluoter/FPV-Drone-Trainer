# 新手學習流程與資料契約

本文件記錄本批採用的產品預設、目前實作邊界及後續開發必須維持的規則。完整待辦仍以 [LEARNING_ROADMAP.md](LEARNING_ROADMAP.md) 追蹤；設計核對、程式完成、自動化驗證與真人試學是不同證據，不能互相代替。

## 已採用的產品預設

| 決策 | 本批採用的規則 |
| --- | --- |
| D01 平台 | 以桌面 Chrome／Edge、1280 × 720 以上視窗為首要目標。手機的課程介紹與示範觀看是後續適配目標，尚未宣稱完成手機驗收。 |
| D02 語言 | 主要教學流程採繁體中文；四軸、Acro、Arm 等術語在教學中附英文。既有進階設定與診斷的全部翻譯尚未完成。 |
| D03 飛行模式 | 從 Acro 觀念開始。新手 preset 降低 rates、採 10° 鏡頭與 90° FOV；不新增自動回平、定高或慢速物理。數值待真人試飛校準。 |
| D04 設備 | USB 遙控器為主要練習方式；鍵盤可體驗、開發與測試。輸入來源分開保存成績；一般手把的完整相容性另行驗證。 |
| D05 順序 | 顯示推薦順序與先備能力，允許跳課。先備資料是建議，不能成為隱藏的選課鎖。一次成功也不等於已熟練。 |
| D06 模式 | 產品分為引導練習、能力挑戰與自由飛行。這一批接上既有挑戰 evaluator 和自由飛行；無限時引導練習尚未實作，詳見下節。示範／個人回放均有明確播放狀態。 |
| D07 資料 | 先使用瀏覽器本機保存；檔案匯出／匯入列後續實作。帳號、雲端同步、排行榜不在本批範圍。 |
| D08 發布 | 短期功能分支 → PR → main → UAT 驗收 → 手動 prod；不新增長期 `uat` 分支。正式站沿用 GitHub Pages。此規則不表示 UAT 部署已建好。 |
| D10 順序 | 先串起 v0.2 新手學習循環，再依試學回饋擴充 v0.3 航線與 v0.4 花飛。既有 Hover、Coordinated Turn、Split-S、Orbit ID 與能力保留。 |

D09 仍待選定：UAT 託管平台、網址與獨立 origin 尚未核對。GitHub Environment 名稱不會建立第二個網站；同一 `github.io` 網域的不同路徑也不會隔離 `localStorage`。發布工作必須在站台確定後接上，不能把本機 smoke 當作遠端部署成功。

## 使用者路徑

以下是畫面與狀態轉移應遵守的路徑；逐項完成度仍由 roadmap 與驗收紀錄追蹤。

| 情境 | 入口、下一步與復原方式 |
| --- | --- |
| 首次進站 | 「開始學飛」→ 認識 Mode 2、Acro 與停止方式 → 看同步示範 → 選 USB 校正或鍵盤體驗 → L01 起飛 → 結果與重試。目前預設選中 L01；L00 以四軸／回中特性介紹與示範呈現，尚不是有獨立通關紀錄的完整課程。 |
| 回訪 | 讀取相同操控條件的本機進度；顯示已練次數與最佳結果，選課或自由飛行。不能因舊有 profile 存在就跳過當次 neutral／連線檢查。自動推薦下一課、恢復上次選課與獨立「繼續練習」入口仍屬後續工作。 |
| 無遙控器 | 可先看四軸與起飛示範，或明確選擇鍵盤體驗。鍵盤成績獨立保存，不能描述成已完成實體遙控器操作驗證。USB 引導入口始終可回到設備設定。 |
| 校正失敗 | 留在設備引導，按訊息重做中心、通道、端點、方向或 neutral 檢查。沒有有效 handoff 不可 Arm；不能用靜默假預設繞過。修正後回原課程，仍需明確解鎖。 |
| WebGL 初始化失敗／context loss | 顯示可見錯誤，runtime 解除解鎖並阻擋 Arm；可重試渲染。畫面恢復後仍需明確重新解鎖，不能在不可見的場景繼續評分。若瀏覽器根本不支援，提示改用支援 WebGL 的桌面瀏覽器；不宣稱軟體降級飛行已提供。 |
| 已熟練使用者 | 可跳選既有進階課，或進入自由飛行；自訂調參留在進階區。切換課程、設定、輸入與播放時仍遵守解除解鎖與重設邊界。 |

主要畫面線框如下。這是資訊層級示意，並非逐像素驗收規格。

```text
┌ FPV 飛行學校 ─ 開始學飛 ─ 自由飛行 ─ 設備與校正 ┐
│ 目前設定：新手／一般／自訂     USB 遙控器／鍵盤體驗 │
├ L00 四軸與 Acro 說明 ─ 橫滾／俯仰／偏航／起飛示範 ┤
│                                                  │
│  3D／FPV 畫面             課程與當前目標           │
│  當前狀態與一項提示       checkpoint              │
│  Mode 2 搖桿             三項主要指標             │
│                                                  │
│  Arm／Disarm／Reset       開始／停止／再練一次       │
├ 結果：完成步驟、主要偏差、下一次修正、回放         ┤
├ 可展開：設備逐步校正／回到原課程                   ┤
└ 可展開：進階調參、診斷與未分類舊版紀錄             ┘
```

選課、目標、提示與 Arm／Disarm 在同一飛行工作區。UI 不可為了切換區塊建立第二個飛行 runtime 或第二條 requestAnimationFrame 迴圈。全螢幕、完整小視窗可用性與長時間操作仍需獨立驗收。

## 課程啟動、停止與播放

啟動採用同一條狀態路徑：

```text
READY
  └─ 開始：解除解鎖、套用課程場景與初始狀態
       → COUNTDOWN（runtime 層禁止 Arm，不評分）
       → WAITING_FOR_ARM（等待明確解鎖，不消耗挑戰時間）
       → 第一個有效 armed=true 固定步進樣本
       → ACTIVE（此樣本同時建立計時起點，elapsed=0 並開始評估）
       → SUCCESS／FAILED → RESULT → 重試／選課
```

- 倒數、等待、無效樣本、缺少 armed 欄位與播放樣本不能產生成績。倒數期間若出現提早解鎖資料，必須先 Disarm，再明確 Arm；不沿用提早解鎖狀態。
- 第一個已解鎖樣本必須通過有限數值、timestamp、場景等檢查；評分以實際位置、姿態、速度與連續軌跡為準，不以搖桿腳本判斷成功。
- ACTIVE 後解除解鎖、失焦、斷線、runtime 重設或墜毀會停止該次挑戰；不能自動重啟或延續原成績。異常數值／倒退樣本被拒絕，不能累積通關證據。
- 改選課程、切換模式、套用 preset／調參、進入示範或回放前先解除解鎖；課程倒數、等待、進行中鎖定調參。重試重新清空 checkpoint、軌跡與 session 狀態。
- 示範與個人回放共用播放／插值功能，但不是 live telemetry。機體、搖桿與字幕讀同一播放時間點；暫停、慢放與拖曳不能餵入課程 evaluator、改變真人飛行狀態或累積進度。退出播放後仍是未解鎖狀態。
- 本批示範來自模擬／可測試資料；不是經飛手核准的教學錄影，也不能證明真人能完成課程。

## 本批挑戰與後續引導練習

| 規則 | 本批實作 | 後續引導練習契約 |
| --- | --- | --- |
| 計時 | 第一個有效已解鎖樣本起算；各課可有逾時規則，例如 L01 為 25 秒。 | 一般練習不因學習等待或目標偏離而逾時；不把 evaluator 的挑戰 timeout 直接套用成無限時練習。 |
| 目標偏離 | 依各課既有 evaluator 重置 dwell、繼續或結束挑戰。 | 一般偏離可重積局部目標；完整重置範圍與提示需逐課定義。 |
| 安全 | 墜毀、失焦／斷線／解除解鎖、重設、無效資料不能通關。 | 維持相同物理與安全邊界；無限時不代表忽略安全故障。 |
| 設定與成績 | UI 啟動使用 `mode: challenge`；新手、一般、自訂與鍵盤／遙控器成績依 context 分開。名稱雖使用「練習」，不代表無限時模式已完成。 | `practice` 有獨立 context；標準條件的獨立挑戰與「熟練」規則仍需實作／校準。自訂或輔助結果不能混為標準通關。 |

本批提供 L01 起飛與四個既有 evaluator；L00 互動完整課程、L03 降落、L04 直線與完整 v0.2 學習循環尚未完成。L01 的 2 公尺相對目標、速度／傾角容許範圍及連續 1.5 秒停留均為原型參數，尚未經新手或實體遙控器驗證。`takeoff-pad.positionM` 是課程起飛初始位置參考；目標為該參考的 Y + 2，不等於模型墊表面的絕對高度。

## 成績 context v1 與舊資料

每次新 UI 挑戰在開始時固定一份 `TrainingAttemptContext`；課程中不得換輸入或設定後仍沿用舊條件。結果保存這份 context，互相比較必須完全相容。

| 欄位 | v1 值與意義 |
| --- | --- |
| `rulesVersion` | `1`；目前共用的課程／判定規則版本。未另設逐課版本欄位；穩定 lesson ID 不代表規則永遠相同。 |
| `physicsVersion` | `1`；物理版本。 |
| `presetId` | `beginner`、`standard`、`custom`；只描述 rates／camera 分類，不能取代完整設定身分。 |
| `settingsFingerprint` | `settings.v1:` 加排序鍵的完整、有限 JSON 設定；保留精確身分，避免短 hash 碰撞。不代表加密或產物完整性驗證。 |
| `inputSource` | `controller` 或 `keyboard`。 |
| `mode` | `challenge` 或 `practice`；schema 支援兩值，UI 目前只啟動 challenge。 |
| `assistance` | `none`；未宣稱其他輔助已實作。 |

context 完整 canonical JSON 編碼後組成 scoped key：

```text
fpv-drone-trainer.training-progress.context.v1.<encoded-context>
```

其內容為 `{ schemaVersion: 1, context, progress }`；`progress` 仍是 `{ schemaVersion: 1, lessons }`。讀取時驗證 context 與 key 相符，再檢查分數、時間、checkpoint、有限指標與已知 lesson ID。新增已知課程用空紀錄補齊，不把未知或舊 placeholder ID 改標成新課完成。

舊 key `fpv-drone-trainer.training-progress.v1` 與既有校正／調參資料保留。舊進度可以顯示為「未分類舊版紀錄」，但不猜測其輸入、preset 或規則版本，也不併入新條件最佳成績。新的 scoped 挑戰不覆寫舊 key；毀損 JSON、未知版本、context 不符或儲存錯誤回報問題，不自動清空或用空文件蓋掉原資料。

UI 以 session ID 防止同一次結果重複保存；重試是新 session。進度 store 的一般 `recordResult` 呼叫本身不是去重資料庫，其他呼叫端也必須遵守一次寫入邊界。重載只恢復相同 context 的次數、最近與最佳，不代表新增了帳號同步、匯出／匯入或永久回放。新手 preset 的切換不默默覆寫原有自訂調參。

規則、物理、輔助或評分條件變更時，需更新相應版本／驗證器並明示相容性；不能只沿用舊 lesson ID 混合排名。UAT／prod 的站台隔離另外由 D09 決定，成績 context 不是部署環境的完整隔離替代品。

## 驗證與限制

純 evaluator／狀態機、mock UI、真實瀏覽器 WebGL、實體遙控器與真人試學分開記錄。自動化 fixture 成功僅證明規則與資料路徑符合該案例，不代表真機手感、飛行擬真度或教學效果已驗證。正式站 HTTPS／資源路徑與 UAT 發布亦需在實際部署後確認。
